# Base 2 — Stacked document

The current base makes readers alternate between a narrow objective column and a goal column. Long objectives create unused space beneath them; labels and edit/remove controls compete with document content. Title, metadata, and action spacing are not consistently hierarchical.

This alternative uses a single reading direction: an objective spans the document above its goals. Each section has a restrained header, a larger objective statement, small numbered goal rows, and aligned editing actions. Optional focus labels retain the exact same structure. Destructive controls are visually quieter. A controlled 880px reading width keeps lines manageable, while the navy navigation stays familiar.

The tradeoff is a longer document than a dense side-by-side layout. This direction prioritises comfortable sequential reading and understanding an objective together with its goals. Nothing is collapsed, truncated, or hidden behind an extra workflow. The document list, separate guide, and spacious per-field dialogs remain intact.

Used the supplied seed, with obvious placeholder text normalised consistently by the parent. Inspected a full-page browser screenshot at 1500px and opened an edit dialog. No infrastructure, storage, or domain features added.
